## Estrategia y límites

El ejecutor exige contexto de RUN canónico, referencia de autorización, `QA_AUTORIZADO=SI`, URL exacta de TEST y nombres de credenciales presentes. En fase preparar sólo se usaron `--comprobar`, `--capacidades`, pruebas de entorno y loopback. Un lanzador externo autorizado podrá invocar el ejecutor; aquí no se creó RUN.

Un Veterinario inicia sesión antes del RUN (120 s). El descubrimiento consulta hasta cuatro páginas de ocho activos individuales y hasta cuatro páginas de historial por cada uno de 32 activos (128 páginas); sigue cursor_siguiente antes de concluir falta de datos. Busca 88 días calendario. Hasta ocho GET /prediccion/modelos/{id} resuelven tipo_modelo nulo mediante id_version_modelo. Las inferencias del mismo activo pueden alimentar casos distintos; la unicidad es por resultado y Veterinario. Se registra en resultado.json un diagnóstico saneado por historial y agregado: tipos de evento, modelos, fechas, riesgo, patología, retroalimentación del usuario identificado por sub del JWT y criterios de descarte con conteos que pueden solaparse. No guarda IDs de usuario, token ni texto clínico libre. Si no puede identificar el usuario, el conteo de retroalimentaciones propias queda nulo y un 409 permite descartar el resultado. Un cursor pendiente o una lectura fallida se señalan en el diagnóstico.

Cada POST tiene una comprobación API independiente. Después de un 201 se lee historial y auditoría por referencia. Si la retroalimentación no aparece en la primera página, se sigue `cursor_siguiente` hasta **tres páginas por activo y comprobación**. Si queda cursor pendiente tras ese límite, NO_CONCLUYENTE; si se agota el cursor sin hallarla, se comprueba la discrepancia. `es_fuente_desconocida` se informa si aparece, sin convertirlo en oráculo adicional. La ausencia de lectura verificable es NO_CONCLUYENTE; una discrepancia comprobada es RECHAZADO. Tres 5xx consecutivos o 403 de clave cortan como BLOQUEADO técnico; un POST sin respuesta exige conciliación y cierre. Siempre se intenta `DELETE /test-control/runs/{id}` después de iniciar el sandbox. Las lecturas poscierre no llevan cabecera de RUN, siguen el mismo cursor hasta tres páginas y buscan ausencia de cada retroalimentación creada. La operación `recuperar` repite el cierre y la conciliación sin nuevos POST.

**Presupuesto máximo exacto: 184 solicitudes**, compuesto por 1 login Veterinario + 4 páginas de activos + 128 páginas de historial de descubrimiento (32 activos x 4) + 8 lecturas de versión + 1 catálogo + 8 POST (hasta cuatro reemplazos) + 12 páginas de historial posteriores (3 por caso) + 4 auditorías + 1 login Administrador opcional + 4 relecturas de auditoría + 1 DELETE + 12 páginas de historial poscierre (3 por caso). Descubrimiento máximo: 142. No hay GET adicional de M09. Timeout: 120 s para logins y 30 s para el resto; duración general de 900 s. El límite de páginas puede dejar una verificación NO_CONCLUYENTE.

## Efectos que deben figurar en la SOL

Los logins pueden crear sesión y auditoría. El listado de activos, catálogo y auditoría son lecturas; `GET historial` materializa eventos y registra `HISTORIAL_CONSULTADO` con `commit` (`src/prediction/application/use_cases/historial_diagnostico/consultar_historial_use_case.py:94-115`). Los GET dentro del sandbox siguen su conexión transaccional (`src/shared/rollback/infraestructure/testing_sandbox.py:35-68`) y se revierten con DELETE (`src/shared/rollback/presentation/test_control_router.py:27-34`). Cada POST crea una retroalimentación, `RETROALIMENTACION_REGISTRADA` y, si hay discrepancia con otro veterinario, `CONFLICTO_RETROALIMENTACION`; el caso 409 no crea registro. Las lecturas **poscierre** generan materialización y auditoría RF-67 fuera del sandbox: la comprobación de rollback sólo acredita ausencia de las retroalimentaciones, no revierte esos eventos. Si falla la persistencia de auditoría RF-73, su repositorio escribe respaldo local en archivo (`src/prediction/infrastructure/repositories/evento_auditoria_m04_repository.py:261-317`; `src/prediction/infrastructure/adapters/respaldo_auditoria_m04_archivo_adapter.py:4,43-62`), fuera del rollback. En las rutas revisadas del POST y repositorios llamados no hay envío de correo, notificación, MQTT ni ONNX; esta conclusión se limita a esas rutas leídas.
