1. RESUMEN EJECUTIVO
--------------------------------------------------------------------------------
Se completo la Fase 1 (solo analisis, consultas read-only en TEST y smoke test
real del camino feliz con periodo_retiro_dias = 0) para TC-M05-G18 sin crear el
script definitivo de pruebas, sin modificar codigo del backend, sin tocar casos
previos y garantizando inocuidad total tras el rollback de cada corrida sandbox.

Conclusiones principales:
- Camino feliz HTTP en TEST: VIABLE y VERIFICADO (`smoke_g18.py`). Sobre el activo
  `853` (limpio, 0 medicamentos previos), abriendo fase dentro del sandbox
  (`id_ciclo_productiva=5`), `POST /suministros/medicamentos` con
  `periodo_retiro_dias=0` respondio `HTTP 201` tanto para `fecha_aplicacion=hoy`
  (`2026-11-10`) como para fecha retroactiva (`2026-11-04`, hoy - 6 dias >=
  `fecha_inicio_ciclo 2026-10-22`), con conteo post-rollback igual a `0` (`HTTP 200
  Rollback exitoso` en todas las corridas).
- S1 (043/011 - Scheduler diario de reversión de retiro): PARCIALMENTE BLOQUEADO
  para prueba E2E por HTTP en TEST (el scheduler `_revertir_retiros_vencidos_diariamente`
  corre unicamente a las 03:00 via `asyncio.create_task` sin endpoint manual ni
  capacidad de avanzar reloj; abre su propia sesion BD fuera del sandbox HTTP; y
  registrar retiro > 0 en TEST dispara SMTP real irreversible). Viable en proceso
  sobre `RevertirRetirosVencidosUseCase` con sesion/dobles controlados. Ademas se
  detecto una brecha de producto en `[LECTURA DE CODIGO]`
  (`notificacion_medicamento_email_adapter.py:72-79`): `notificar_fin_retiro`
  SOLO envia correo al Productor y NO al Veterinario.
- S2 (044/012 - Falla RF-44 al pasar a EN_TRATAMIENTO): BLOQUEADO por HTTP en TEST
  (no existe inyeccion de fallos en `/test-control`), pero 100% VIABLE EN PROCESO
  con `TestClient` + `dependency_overrides` + `monkeypatch`. En codigo ya esta
  resuelto el conflicto FA-10 vs E10 a favor de RF-76 E10: rollback atomico +
  `HTTP 500` con `error_code="ERROR_ESTADO_EN_TRATAMIENTO"`.
- S3 (047/042 - Falla calculo `fecha_fin_retiro` / BD): BLOQUEADO por HTTP en TEST;
  VIABLE EN PROCESO con `TestClient` + `dependency_overrides` + `monkeypatch` para
  fallo de persistencia (FA-13). `fecha_fin_retiro` (FA-09) es aritmetica pura en
  Python sin `try/except` propio ni auditoria separada.

def _sanitizar(obj: Any) -> Any:
    if isinstance(obj, str):
        s = obj
        for sec in _secretos():
            s = s.replace(sec, "***")
        jwt_pref = "ey" + "J"
        if jwt_pref in s:
            s = s.replace(jwt_pref, "[JWT_OMITIDO]")
        return s
    if isinstance(obj, list):
        return [_sanitizar(x) for x in obj]
    if isinstance(obj, dict):
        return {str(k): _sanitizar(v) for k, v in obj.items()}
    return obj


def _login(s: requests.Session, base: str, email: str, pwd: str) -> dict[str, Any]:

def _env(nombre: str) -> str:
    return (os.environ.get(nombre) or ENV_TEST.get(nombre) or "").strip()


def _secretos() -> list[str]:
    res = []
    for k in (
        "TEST_SANDBOX_SECRET",
        "TEST_ADMIN_PASSWORD",
        "TEST_ADMIN_EMAIL",
        "TEST_PRODUCER_PASSWORD",
        "TEST_PRODUCER_EMAIL",
        "TEST_VET_PASSWORD",
        "TEST_VET_EMAIL",
        "TEST_FIELD_ENGINEER_PASSWORD",
        "TEST_FIELD_ENGINEER_EMAIL",
        "TEST_DATABASE_URL",
    ):
        v = _env(k)
        if v:
            res.append(v)
    return res


def _sanitizar(obj: Any) -> Any:
    if isinstance(obj, str):
        s = obj
        for sec in _secretos():
            s = s.replace(sec, "***")
        jwt_pref = "ey" + "J"
        if jwt_pref in s:
            s = s.replace(jwt_pref, "[JWT_OMITIDO]")
        return s
    if isinstance(obj, list):
        return [_sanitizar(x) for x in obj]
    if isinstance(obj, dict):
        return {str(k): _sanitizar(v) for k, v in obj.items()}
    return obj
