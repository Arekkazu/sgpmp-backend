Contrato

POST /finanzas/cotizaciones recibe activos_cotizados como enteros y valor_cotizacion_propuesto mayor que cero. No acepta un UUID ni un período. El orden es: activo inexistente responde 404 ACTIVO_NO_ENCONTRADO; estado distinto de ACTIVO o sin reconocimiento responde 422 ACTIVO_NO_DISPONIBLE; sin cálculo CALCULADO responde 422 VALOR_RAZONABLE_NO_DISPONIBLE. Esas tres ocurren antes de resolver el período. Un período cerrado no se rechaza: periodo_para usa el primer período abierto posterior o crea uno, y después inserta. Esa solicitud no se envía. El diseño pedía 422 también para el activo inexistente.

Hallazgos

  • QUESTION-M06-G116-01: el activo inexistente responde 404 ACTIVO_NO_ENCONTRADO. El diseño esperaba 422. El DTO solo acepta enteros, no UUID.
  • QUESTION-M06-G116-02: un período cerrado no impide la cotización. El caso de uso la lleva al período abierto posterior y la guarda. Esa solicitud no se envió.
