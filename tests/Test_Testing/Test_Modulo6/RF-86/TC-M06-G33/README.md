## Selección y preparación

El ejecutor consulta activos bovinos `INDIVIDUAL`, `ACTIVO`, sin valoración por costo y con valor razonable positivo. Requiere precio vigente `PESO_KG`, período destino `ABIERTO` del titular, peso actual kg y cálculo previo `CALCULADO` positivo. El período destino sigue la regla de `contabilizador.py:39-66`: si el período de hoy está cerrado, se usa el primer abierto posterior; `EN_CIERRE` impide el caso. Se prefieren candidatos cuyo cálculo previo usa el precio vigente. Si el precio o la magnitud previa difieren, se registra y procesa primero un evento con el mismo peso, se comprueba el cálculo actualizado y se fija después la línea base del caso. El rebase queda fuera del oráculo. No se fijan IDs de TEST ni se registran precios.

La línea base incluye variaciones del período, líneas, mediciones, historial financiero del activo, auditoría técnica del activo y período, bandeja del Contador QA y eventos M02. Se registra un único evento del caso con el peso actual, sin modificar cantidad ni condición. Tras `POST /finanzas/eventos/procesar`, se contrastan las seis lecturas. Se exige ninguna variación ni línea nueva del activo, ninguna medición o cálculo nuevo y mismo cálculo último con valor positivo, exactamente una auditoría `MEDICION_SIN_VARIACION` con referencia al evento, severidad `INFO` y período destino, y ninguna alerta nueva de error en auditoría o bandeja. Una discrepancia comprobada produce `RECHAZADO` y una incidencia; lectura incompleta produce `NO_CONCLUYENTE`; ausencia de datos imprescindibles produce `BLOQUEADO` con condición.

La bandeja se ordena por `fecha_envio DESC, id_notificacion DESC` (`src/identity_access/infrastructure/repositories/notificacion_repository.py:167-169`); el router admite `pagina` y `tamano` hasta 50 (`src/identity_access/infrastructure/routers/notificaciones_routers.py:37-38`). Se fija la clave de recencia del primer aviso previo al evento y se leen después las páginas necesarias hasta alcanzarla. Los avisos anteriores quedan fuera de la comparación aunque el total supere 50. Un aviso nuevo solo constituye alerta del caso si su mensaje o campos vinculan el activo, su identificador o el evento M02 y además expresan error; los demás se cuentan como observación. `MEDICION_PENDIENTE` es un tipo de auditoría M06 real (`src/financial_valuation/application/use_cases/valoracion/procesar_eventos_m02_use_case.py:124`, `src/financial_valuation/application/services/medidor.py:150`). El `id_evento` numérico de la bandeja pertenece a M01 (`src/identity_access/infrastructure/schema/notificacion_schema.py:11`) y no se presume igual al evento M02. La auditoría M06 conserva los filtros de activo y período y pagina hasta `total_registros`, con límite de 500 por página (`src/financial_valuation/infrastructure/routers/m06_router.py:500-508`). Una lectura que no alcance la línea base o el total queda incompleta.

## Contrato y presupuesto

`node g33.mjs --capacidades` anuncia `sigab-qa-ejecutor/1`. `--comprobar` valida rutas locales. Una evaluación real solo puede ser invocada por el lanzador externo con `--operacion evaluar|reintentar|reevaluar --version N --intento N --run-id RUN-G33-VN-AAAAMMDD-HHMMSS --autorizacion REFERENCIA --contexto RUTA`, contexto coherente, `QA_AUTORIZADO=SI` y RUN creado previamente. Los dos logins ocurren fuera del RUN. Dentro del RUN se limitan a dos eventos M02, dos procesamientos, cero precios, cero PATCH y lecturas públicas; máximo 60 solicitudes y 900 s. Login y POST tienen timeout de 120 s; las demás solicitudes, 30 s. No hay reintentos. Un POST sin respuesta se concilia por lectura. Se corta con 403 o tres respuestas 5xx principales consecutivas.

La colección Newman hace dos GET con aserciones, ejecutada como hijo mediante `process.execPath`; su consulta de auditoría usa `orden=DESC` para que el evento del caso aparezca en la primera página aun con historial anterior abundante. Su exportación temporal se ubica en `os.tmpdir()`. En un RUN real se guardan `resultado.json`, un solo informe Markdown oficial y los resúmenes JSON/HTML de Newman bajo el mismo RUN. El DELETE lleva `X-Sandbox-Secret`; el rollback solo se marca verificado con lecturas públicas posteriores que no muestren eventos M02, auditoría del RUN ni registros financieros creados. Si falla DELETE, no se atribuye rollback.

El ensayo `node pruebas/g33_ensayo.mjs` usa solo loopback y no crea RUN ni informes. La ejecución de TEST y sus posibles efectos de login, evento M02, procesamiento M06 y auditoría requieren autorización particular del lanzador externo. No se ha consultado TEST en esta preparación.
