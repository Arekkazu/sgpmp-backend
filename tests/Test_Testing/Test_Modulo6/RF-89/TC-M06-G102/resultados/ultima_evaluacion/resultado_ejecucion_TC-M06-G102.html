Dependencia del precio 436

La API de precios solo expone GET /finanzas/precios y POST /finanzas/precios. No hay una operación para editar, borrar o cerrar la vigencia del precio 436. El alta es acumulativa: el registro anterior permanece y, al leer, el servicio marca como SUPERADO al precio de la misma fuente que deja de ser el más reciente.

Antes del alta, el 436 estaba ACTIVO y aplicado, y el 437 estaba ACTIVO y no aplicado. El umbral era 50 %. Había cero activos reconocidos de la especie 424. La consulta biológica por especie sigue fuera del alcance del Contador, así que no se afirma la ausencia de activos no reconocidos.

El subcaso 16 es la operación que reemplaza la referencia aplicada. No se ejecutaron TC-M06-32 ni TC-M06-33. Después del alta, la referencia vigente de MERCADO_ACTIVO es el precio 489, por 5.000.000. El 436 sigue en el historial, con el mismo importe y la misma fecha, en estado SUPERADO.

Pendiente de contrato y de regresión

RF-89 v1.1 pide HTTP 400 cuando la justificación estimada tiene menos de 50 caracteres. En laura ese rechazo sigue asociado a HTTP 422 y el PR #1024 no se dio por desplegado. No se envió una justificación corta. Los subcasos 19, 20 y 21 no se ejecutaron. TC-M06-32 y TC-M06-33 tampoco. La referencia vigente que esos dos subcasos necesitaban, 4.000.000, ya no es el precio aplicado; el registro 436 permanece como historia superada.
