Collection: RF-53 - TC-M03-G04 Rechazo de timestamp_captura futuro (desincronización de reloj)
Collection Description
Automatiza TC-M03-011 (RF-53, CU01, flujo alterno E7). Envía a POST /iot/telemetria tres lecturas del mismo sensor con timestamp_captura = hora del servidor, +1 s y +2 h. La hora del servidor se estima con el header Date de la respuesta anterior (resolución de 1 s), así el resultado no depende del reloj de quien ejecuta. Esperado según la ficha: la primera 201, las dos futuras 400 ERROR_TIEMPO, y en el historial (RF-59) solo la primera. Nota: el código actual tolera 30 s de desfase NTP hacia el futuro (_MAX_DRIFT_FUTURO_SEG), así que +1 s se aceptaría; la ficha no contempla esa tolerancia. La bitácora de ingesta no tiene endpoint de consulta. La colección crea sus propios datos: finca, especie, galpón, dispositivo y sensor. Desde DEV-06 los endpoints /iot/* de dispositivo exigen el token de servicio del broker (Authorization: Bearer) y el campo access_key pasa a llamarse serial (identidad del nodo, no credencial): el token NO se versiona, se pasa con newman --env-var broker_token=<BROKER_SERVICE_TOKEN de TEST>.
