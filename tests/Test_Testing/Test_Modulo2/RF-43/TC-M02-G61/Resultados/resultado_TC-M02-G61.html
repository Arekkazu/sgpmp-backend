Se repite aqui con tipo_baja=muerte (en vez de venta, ya usado en TC-M02-G58) para reforzar que el bug no es especifico de un tipo_baja -- es cualquier baja TOTAL. Sub-caso 3 (TC-M02-113, baja PARCIAL de lote): no depende de RF-37 ni cae en el bug de cierre de TC-M02-G58 (cantidad_actual no llega a 0, nunca se llama _procesar_baja_con_cierre) -- se esperaba camino feliz (201), pero se encontro un BUG NUEVO independiente: el endpoint responde 400 VALOR_FUERA_DE_RANGO (DataError) de forma 100% reproducible, confirmado en dos lotes distintos. HALLAZGO NUEVO (de infraestructura de pruebas, distinto al bug de arriba) (encontrado armando este sub-caso): el trigger modulo2.trg_fn_evento_fecha_coherente (BEFORE INSERT en eventos_activos) rechaza cualquier evento cuya fecha sea anterior al fecha_creacion EXACTO (con hora) del activo.
