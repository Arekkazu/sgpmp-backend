Collection: TC-M09-G124 (TC-M09-240/241)
Collection Description
Auditoria de aplicacion exitosa/fallida de plantillas (RF-32, OWASP A09). Revisando el codigo fuente actual (solo lectura) de AplicarPlantillaUseCase se confirmo que SI existe un repositorio dedicado (AplicacionPlantillaRepository, tabla modulo9.aplicaciones_plantillas) que registra cada aplicacion exitosa con snapshot antes/despues, expuesto via GET /configuracion/plantillas/historial -- por eso el historial ya contiene aplicaciones reales previas. Pero esa llamada solo existe en el camino de exito (dentro del try, justo antes del commit): en el except que hace rollback() no hay ninguna llamada a este ni a ningun otro repositorio de auditoria. El endpoint generico GET /auditoria/ tampoco cubre esto en ningun caso, porque su catalogo de tipos_evento solo abarca el modulo de identidad. Este test intenta una aplicacion (que ademas ya sabemos que falla con 500 por el defecto de TC-M09-G118/G122) y verifica en vivo que ese fallo -- a diferencia de un exito -- no deja ningun rastro ni en /auditoria/ ni en el historial de aplicaciones. Ejecutar con: newman run tc-m09-124.json --reporters "cli,htmlextra" --reporter-htmlextra-export resultado-124.html
