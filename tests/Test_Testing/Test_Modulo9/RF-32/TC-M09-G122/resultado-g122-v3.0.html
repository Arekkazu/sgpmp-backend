Collection Description
Retest de TC-M09-G122 (TC-235/236). El retest v2.0 (2026-09-12) confirmo el defecto: el sistema aplicaba una version SUPERADA de una plantilla exactamente igual que la vigente (200 OK en ambas), sin ninguna restriccion. Antes de correr esta v3.0 se releyo el codigo fuente y se encontro que ya se agrego la correccion: `AplicarPlantillaUseCase._ejecutar` (INC-M09-03-122 / #317) ahora compara la version de la plantilla contra `plantilla_repo.obtener_ultima_version(template_name)` y, si no coincide, lanza `BusinessRuleError(code='PLANTILLA_VERSION_NO_VIGENTE')` -- que el manejador global de AppError traduce a HTTP 422. Esta version deja de conformarse con 'no responder 200' (como hacia la v2.0, cuando no habia ningun codigo de error que verificar) y ahora exige el status 422 y el error_code exactos que el codigo produce. Ademas, en vez de mandar `fecha_actualizacion_especie_destino: null` a ciegas (en la v2.0 eso solo funcionaba porque la especie destino elegida por casualidad tenia ese campo en null), esta version captura el valor real de la especie destino (paso 0B) y lo reenvia tal cual como JSON valido (null o la fecha entre comillas), para no arriesgar un 409 CONFLICTO_CONCURRENCIA espurio si esta vez la especie elegida si tiene fecha_actualizacion.
