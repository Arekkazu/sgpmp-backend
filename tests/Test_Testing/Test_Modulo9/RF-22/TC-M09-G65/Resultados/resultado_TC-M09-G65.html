Collection Description
TC-M09-G65 (RF-22, CU-05 Gestionar Dispositivos IoT), equivalente a TC-M09-124: verificar que POST /configuracion/sensores/{id_sensor}/asociar solo pueda ser ejecutado por los roles autorizados. Contrato RBAC real (src/configuration/infrastructure/routers/sensor_router.py, id_recurso=12 'sensores', id_accion=1 'Crear'): Admin e Ingeniero tienen permiso de Crear (C=1) sobre este recurso; Productor y Veterinario solo tienen Leer (R=2), sin permiso de asociar. El gate lo aplica require_permission (src/shared/rbac.py) consultando modulo1.permisos en cada request; si el rol no tiene el permiso activo lanza AuthorizationError -> HTTP 403, error_code ACCESO_DENEGADO. Escenarios cubiertos: 1. Rol autorizado (Administrador, tiene C=1 sobre recurso 12) -> la asociacion se ejecuta, HTTP 201. 2. Rol NO autorizado (Productor, solo tiene R=2 sobre recurso 12) -> HTTP 403, error_code ACCESO_DENEGADO, y el sensor queda SIN esa asociacion (verificado consultando el historial con el token de Administrador). La coleccion es autocontenida: el Administrador registra su propio dispositivo IoT y 2 sensores de prueba sobre un area productiva activa ya existente en TEST (finca_id=1) -- uno para el escenario autorizado y otro distinto para el escenario denegado, evitando que el resultado del primero (asociacion ya vigente) contamine el segundo con un 409 en vez de un 403. La cuenta Productor usada (u20221206763@usco.edu.co, id_usuario=58) fue provista por el usuario como cuenta activa de referencia para pruebas RBAC negativas (ya usada en TC-M01-110 y TC-M09-G58). Responsable: Juan Pablo. Prioridad: Alta. Tipo: Pruebas de seguridad. Herramienta: Newman.
