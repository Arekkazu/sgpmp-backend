## 4. Hallazgos que Refuerzan Incidencias Vigentes

### A) Refuerzo a `INC-M09-62-G03` (Issue #231 en Taiga)
- **Comportamiento en NW-05 y NW-07**:
  Al invocar `PATCH /configuracion/especies/{id}` sobre la especie recién creada (`id_especie=103`), el servidor rechazó las peticiones con `HTTP 400 VAL_ENTRADA`.
- **Análisis de Causa Raíz**:
  1. `RegistrarEspecieUseCase` ([src/configuration/application/use_cases/especies/registrar_especie_use_case.py:61-67](file:///c:/Users/Juansegutt/Integrador/sgpmp-backend/src/configuration/application/use_cases/especies/registrar_especie_use_case.py#L61-L67)) persiste entidades inicializando únicamente `fecha_creacion`. La columna `fecha_actualizacion` queda con valor `NULL`.
  2. `EspecieModel` ([src/configuration/infrastructure/models/especie_model.py:47-50](file:///c:/Users/Juansegutt/Integrador/sgpmp-backend/src/configuration/infrastructure/models/especie_model.py#L47-L50)) define la columna como nullable.
  3. `EditarEspecieDTO` ([src/configuration/infrastructure/dto/editar_especie_dto.py:26](file:///c:/Users/Juansegutt/Integrador/sgpmp-backend/src/configuration/infrastructure/dto/editar_especie_dto.py#L26)) define `fecha_actualizacion: datetime` como obligatorio. Al llegar `null` o cadena vacía `""`, Pydantic aborta con HTTP 400.
  4. Si el cliente envía cualquier datetime (como el workaround `new Date().toISOString()` del frontend), `EditarEspecieUseCase` ([src/configuration/application/use_cases/especies/editar_especie_use_case.py:76](file:///c:/Users/Juansegutt/Integrador/sgpmp-backend/src/configuration/application/use_cases/especies/editar_especie_use_case.py#L76)) evalúa `elif ts_actual != ts_dto` (`None != <datetime>`), arrojando `HTTP 412 Precondition Failed`.
- **Veredicto**: Este caso **NO abre incidencia nueva**. Constituye evidencia reproducible pura de backend para el issue **#231**.

### B) Refuerzo a `INC-M09-01-G01 v2.0`
- **Comportamiento en NW-04b y NW-08b**:
  Tanto en la creación como en los intentos de edición, el campo `grupo_manejo` fue ignorado silenciosamente y no forma parte del modelo ni de los snapshots JSONB en `modulo9.auditorias_especies` (`valores_anteriores` ni `valores_nuevos`).
- **Casos Afectados Actualizados**:
  Se incorpora formalmente `TC-M09-G08-v2.0` a la lista de casos afectados por este defecto raíz:
  `G01`, `G02`, `G03`, `G07`, `G08`.

## 5. Hallazgo Descartado de Arnés (c): NW-06
- **Descripción**: El consolidador inicialmente marcó NW-06 como OK en base de datos al encontrar el registro `id_auditoria_especie = 206` con la transición `'Cabra Qab' -> 'Cabra Criolla Qab'`.
- **Detección de Falso Positivo**:
  Al analizar la cronología completa de auditorías para `id_especie = 103` sin filtro temporal, se constató que la auditoría 206 se registró a las `04:48:32 UTC`, varios minutos después de que la colección de Newman finalizara y producto de una invocación manual con Python durante la fase diagnóstica.
- **Acción Correctiva**:
  NW-06 se removió del arreglo computable principal `checkpoints` y se registró en `checkpoints_no_contabilizados`.
- **Mejora Futura para el Arnés**:
  Se recomienda que `verificar-bd.py` aplique filtros temporales estrictos acotados al intervalo exacto de inicio y fin de la corrida de Newman (`run_start_time` y `run_end_time`), evitando que consultas manuales posteriores contaminen la verificación.
