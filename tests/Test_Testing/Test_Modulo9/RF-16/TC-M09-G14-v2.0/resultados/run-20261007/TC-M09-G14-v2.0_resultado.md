## 5. Preflight Implementado y Selección Dinámica de Nombres

### A) Diagnóstico de la Corrida Fallida Previa
En la primera ejecución, los 7 intentos de creación fallaron con HTTP 409 Conflict. La causa raíz técnica en el backend es que `metrica_produccion_repository.py` valida:
`WHERE LOWER(nombre) == nombre.normalizado() AND id_especie == id_especie`
**sin discriminar si el registro existente está activo o inactivo**. Al haber sido creados y desactivados en ejecuciones previas, los nombres base quedaron permanentemente ocupados en la base de datos TEST. El fallo fue clasificado estrictamente como **(c) Defecto del arnés de prueba por carecer de preflight dinámico de nombres contra catálogo**.

Se reemplazó el ítem NW-02 por una secuencia doble:

## 8. Observación de Arquitectura (SC03: HTTP 422 vs 400)

En el subcaso SC03 (combinación incoherente `PESO` con `litros`), la hoja de diseño original sugería HTTP 400, pero el backend responde **HTTP 422 Unprocessable Entity** (`error_code: "UNIDAD_MEDIDA_INCOHERENTE"`).
- **Razón Arquitectónica**: La validación de tipos primitivos sintácticos (FastAPI/Pydantic) emite HTTP 400 (`VAL_ENTRADA`). La coherencia semántica entre unidad y tipo es una regla de dominio de negocio evaluada en `RegistrarMetricaUseCase` vía `BusinessRuleError`, la cual la capa web traduce a HTTP 422.
- **Veredicto QA**: Es un comportamiento arquitectónicamente superior y consistente con el diseño hexagonal del sistema. Se clasifica formalmente como discrepancia de especificación no bloqueante (`b`), NO es un defecto, NO se reporta a Taiga y se considera validación plenamente superada.
